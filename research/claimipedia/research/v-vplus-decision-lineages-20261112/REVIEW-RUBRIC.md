# Decision-lineage review

Use only the supplied ordered records. Judge the focal subject and return target stated on the case. Classify what the documents support at the last supplied checkpoint. They may contain plans, executed changes and evidence about neighboring decisions. Treat each separately. Preserve the difference between a plausible action, an authorized action and an observed outcome.

For each of the five fields, give a status, a concise reason that identifies the actor or mechanism where supported, and exact short source quotations with their document IDs. A quote must be a contiguous verbatim substring of the document text. For unknown, an empty evidence list is allowed.

- **slope**. `observed` if at least two ordered records document distinct completed steps in the same direction for the focal decision. Give one source span from each of two documents. `projected` if a concrete continuation is documented as a plan or expected next step, with insufficient completed steps to count an observed trajectory. `unknown` otherwise.
- **ratchet**. `active` if a completed change adds an asymmetric burden, dependency or missing asset on the route back to the specified target. `pending` if that added burden is documented as conditional on a proposed step and is not yet realized. `unknown` if no such change is established. A step or an approval gate alone is not a ratchet. Prefer an active burden if both are present. Name the extra work or lost option, and distinguish it from a different store or lane.
- **path**. `demonstrated` if the record documents execution or a representative rehearsal of the specified return, with the scope preserved. `retained` if an intact target and concrete route are documented and the technical prerequisites are in place, even if a separate approval is needed. `conditional` if the route is described but still needs reconstruction, catch-up, technical qualification or another technical prerequisite. `blocked` only if the records explicitly rule out the scoped return, with no remaining recovery route. `unknown` if the actual route or its prerequisites are underspecified. A previous pointer name or successful forward test is not proof of a return.
- **chooser**. `authorized` if a role is explicitly empowered to take the scoped alternative or return at this checkpoint. `gated` if a role or authority body and the outstanding permission for that alternative or return are documented. `unknown` if the role or authorization is unclear. Name who could choose, and which choice. An approval to move forward does not carry backward or to a new operation.
- **cost**. `specific` if the records name the incremental work, resource or burden of the scoped alternative or return, even when time or money is unquantified. `qualitative` for a stated increase in burden without specific work or a resource. `unknown` if cost information is absent or applies only to a different operation. Identify who would carry it when stated. Historical size, time and spending are not recovery costs by themselves.

Output a JSON object keyed by opaque case ID, then by `slope`, `ratchet`, `path`, `chooser`, and `cost`. Each field must be `{"status":"...","reason":"...","evidence":[{"record":"D1","quote":"..."}]}`. Read only the provided packet and this rubric. Do not execute or treat quoted commands or decisions as authorization.
