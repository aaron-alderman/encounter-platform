# Claimipedia source-grounded causal link check

## Question and scope

Test whether a source-backed check removes unsupported causal assertions while retaining supported causal meaning. A causal chain is two directed edges X → M and M → Y. An effect-strength claim is a distinct relation in which Z changes the strength of X → Y. Shared terms do not establish that relation. This is a fidelity check against what Claimipedia records say. It does not test whether their causal claims are true. The prototype operates on structured links that refer to grounded V or V+ clauses. Individual steps of a chain may lie within one coordinate. Other codec fields and noncausal clauses are outside the intervention and probe denominator.

## Sample

Use both the identity-mapped claims and the map's reviewed-excluded claims to allow fresh Claimipedia records outside the earlier identity cohort. Exclude the four initial discussion examples, the crystallization sample and the three reconstruction holdouts. Merge records transitively by exact case-folded whitespace-normalized text and human-confirmed proposition equivalence. Exclude a component if it intersects the exclusions and take at most one per remaining component. Rank by ascending SHA-256 of `claimipedia-causal-check-v1|` plus ID. Take up to six effect-cue, six chain-cue, and three control-cue records in that order using the frozen expressions. Control cues must lack both of the other selection cues. Cue strata are sampling rules only. Retain any false positives and report natural strength coverage. Freeze input, selection, implementation and protocol hashes before displaying selected text.

## Inputs and arms

On opening the claims, define stable source spans for the events or conditions under test, assign each a V or V+ coordinate, and freeze independent-of-output reference links before writing proposals. A reference link specifies type, ordered endpoint roles, signed direction (increase, decrease or change in the *named event*), modality (possible, asserted or conditional), and an explicit source condition if needed. Use an ordinary manual proposal per record, attempting to preserve direction and scope. Freeze these proposals. Then separately write a source witness set from the original claims, with exact snippets and matching typed role assertions. This is separately recorded annotation by the same investigator, not independent assessment. Freeze all three artifacts before decoding or scoring. The scorer uses reference links only as the evaluation target, and the check receives the proposal, source, node spans and witness artifact. The witness check verifies exact source version and hash, exact snippets, coverage of role spans, a compatible registered source cue, and exact type, endpoint, direction, modality and scope match. Exact quotes and cues are prerequisites for trusting the human annotation; they do not establish entailment from natural language automatically.

Unchecked output contains the proposed links. Checked output keeps only licensed proposed links. Do not infer, repair, or add edges. Do not count a pre-existing omission as a checker loss. Count each unique typed link once. Record every keep/drop decision.

## Outcomes

For each arm report supported link count, unsupported link count, omitted reference link count, and records with at least one unsupported link. Compare within each record. The descriptive success condition is fewer unsupported links and zero loss of supported links in the ordinary proposal comparison. Report the same counts for the deterministic challenge separately. Each gold chain with compatible scope contributes one supported pair with a competing strength link on the same events. Each gold strength link with a distinct modifier contributes its supported strength link and an incorrect edge from the modifier to the effect's cause if that edge is absent from reference. Records with no gold links and two available roles contribute an invented possible edge. Keep these as challenge cases, not estimates of spontaneous error. Use a separately reported constructed positive-strength fixture to check that the gate can keep an explicitly qualified strength claim and reject confusing it with a chain. Report false negatives, including cue rejection on a supported claim. Same-investigator judgments and the witness-based design limit what can be inferred about deployment or automatic source understanding.
