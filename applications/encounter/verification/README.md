# First-loop verification

This is engineering evidence from one session/family, not independent human
usability or compiler/security verification. Browser automation constructs app
state through visible controls only. It never installs application schemas,
programme graphs or witness snapshots. Test helpers own browser lifecycle and
form operations, not application policy. Native mechanism fixtures are separate.

Current-source evidence is identified in `release-ledger.rel`. The journal and
harbour domains start from separate empty stores. They exercise:

- intent and reason/target/goal on reviewed durable changes;
- type creation and one-field evolution with explicit existing-data resolutions;
- Text, Number, Boolean, nominal Reference and independently aliased roles;
- GUI/text edits, inert dollar text, invalid drafts, cancellation and stale review;
- web/row projections, explicit contextual overlay and input/rule inspection;
- authored source actions, GUI construction, execution, compatible upgrade,
  incompatible-output refusal and forward-checked partial inverses;
- revision restoration, queued/cancelled/resumed local export, retained artifact;
- desktop/mobile overflow and focus checks, then a genuine new-process reopen.

Nine contract/storage tests cover closed types, branch inference and ambient
action refusal, alias/reference refusals, forged/raw/copy admission refusal,
atomic CAS, metadata-bound replay, real process death on either side of COMMIT,
operation reconciliation and incompatible profile refusal. Two additional real
browser fault cases prove known rollback requires a new explicit click and a
lost post-commit response does not duplicate the accepted revision.

`foundation-provenance.tsv` records all 87 selected dependency files and exact
hashes, alongside a later observation of the origin checkout. Two origin files
changed after selection (the admission implementation and its pinned manifest).
The restart retains its internally pinned selected snapshot; those later changes
are not merged or claimed tested here. Origin is a working checkout, so its base
Git commit alone is insufficient provenance. Vendor licenses remain included.

Earlier numbered logs/receipts are retained counterexamples and iteration
history, not additional independent confirmations. Earlier witness stores with
the pre-release schema cannot be opened by the current runtime; no migration is
claimed. Failure screenshots remain local and ignored by Git. Current final
screenshots are identified by the release ledger and were visually inspected.

The earlier design's cold-ready target was five seconds; observed browser-test
startup times are in the harbour receipt. Startup compilation is still a material
cost. This run does not establish edit-feedback or view-update p95 targets, large
project performance, independent command discoverability, or a full accessibility
audit. Keyboard/focus, label and narrow-screen checks are a bounded QA pass.

Still outside this first loop: the complete eight-page event app; full Mainframe
operation; graphical/spatial/agent authoring; arbitrary nested user values and
programme forms; multi-user authorization; self-upgrading the authoring environment;
and text/GUI parity for every possible action expression and metadata operation.
Those broader obligations are preserved, not marked complete by these witnesses.
