# Creator Studio implementation and assurance

## Authority and source ownership

Aaron authorized the full product direction and application implementation on
9 November 2026, requiring Encounter only. Application definitions, processes,
validation, projections, commentary, standardization, workflow choices and
acceptance policy must be authored in Encounter. No new handwritten JavaScript,
MJS helper, opaque callback or executable JSON module may supply application
behaviour. Generated process JSON and native bundles are derived artifacts.

The candidate will use the retained Encounter compiler, lowering, admission,
kernel, inverse-edit route and generic native mechanisms from
`applications/usewords-lightning`, with exact predecessor provenance. That
application remains untouched. New suite work belongs in an isolated
`applications/creator-studio` candidate. Existing native files and vendor files
must remain byte-identical; any additional effect requires its explicit mature
capability route rather than an application-specific script.

Source documentation is retained in this programme and the linked Worldwright
account. Machine-executable application policy is Encounter source. The running
suite should also expose the product account and source inspection.

## Delivery obligations

1. Document product and meta-product before application implementation.
2. Establish one typed project and the common propose/check/review/accept path.
3. Make all seven workspaces functional through that path.
4. Compile useful outputs with source identity and selected standards.
5. Preserve original inputs and explicit decompilation gaps.
6. Make scenarios, journey selection, commentary, standards and package exchange
   usable rather than decorative navigation.
7. Test real semantic consequences and failure cases through Encounter.
8. Render and inspect representative app journeys, narrow layouts, keyboard
   access, text contrast, persistence and import/export before release.

## Implemented release: 9 November 2026

The isolated application is `applications/creator-studio`. It implements a
browser-local professional production composition through Encounter. All seven
workspaces operate on one typed project through `cs.edit` → `ws.apply` →
`ec.patch`; the application has no independently accepted client graph.

| Workspace | Working capability in this release | Output |
| --- | --- | --- |
| Documents | Create records, edit supported heading/paragraph source and editorial notes, bind named values, preview selected terminology. Retain original imported text and make an explicit working copy. | HTML or Markdown; original plain text. |
| Tables and Models | Create/edit named inputs and calculations, check dependencies and units, inspect a same-unit chart and preview a changed scenario. | CSV model and SVG chart. |
| Presentations | Create/edit slide source, navigate previews and retain speaker notes. Slides share the model and selected prose standard. | Standalone HTML with print layout. |
| Canvas | Create/edit identified nodes, explanations, coordinates and directed relationships. Diagram text wraps; a description retains the map's meaning. | Self-contained SVG. |
| Media | Create/edit scripts, scene durations and captions; reorder or remove draft scenes and inspect the timed storyboard. | WebVTT captions and retained production source. |
| Workflows | Choose narrative, budget or co-design approaches; add/update/reorder/remove declared steps. Validate accepted source and compile five production formats with hashes. | Inert execution report containing the actual artifacts. |
| Review and Commentary | Propose, inspect named-value and standards impacts, compare retained versions, retain attributed comments with their rendered original context, save after exact replay, or discard the draft. | Review records and portable project/version packets. |

Library, Standards, Exchange, Inspect and the product guide are supporting
perspectives. Project name, client and purpose are editable. Methods carry their
required named values, workflow, selected standard, attribution, version,
licence and stated exchange terms. Import checks their closed data grammar;
adoption stages changes for review. The included catalogue is explicitly
authored demonstration material, not a claimed live community marketplace.

### Reproduction and evidence

From `applications/creator-studio`:

```text
npm test
node bootstrap/build.mjs
node bootstrap/cli.mjs creator-rendered-assure assurance/browser-rendered.request
```

`assurance/results.json` records the current source cases, exact process identity
and actual usage against the unchanged budget. Cases cover the initial and blank
project, 30→48 calculation, immutable baseline, exact replay, stale edits,
duplicate identities, cycles, incompatible units, malformed and unknown
bindings, escaping, selected terminology, CSV formula shielding, caption-time
carry, self-contained diagrams, same-unit charts, workflow artifact hashes,
method effect refusal, forged receipts, schema substitution and malformed
project protocols. Standards impact is checked independently of a model change.

Browser observations exercise the actual host, including accepted-versus-draft
exports, a two-change reviewed version and reload, source import and working
copy, complete project packet export/import, method export/import, method
preview/discard, calculation refusal/correction and keyboard navigation. The
downloaded five-artifact run was checked against its bytes and source hash.
The browser and source runs are complementary evidence, not independent
confirmations of the same scientific claim.

Rendered observations are retained as inert packets. Contrast ratios and
threshold decisions run in Encounter. The DOM sampler covers opaque text and
nearest solid backgrounds; gradient composition, SVG glyph geometry, native
menus and cross-platform font differences require additional visual inspection.
Reflow is checked at an observed 320 CSS-pixel viewport (303 usable pixels with
the scrollbar), with the roomier text option enabled. Tables and diagrams have
their own labelled, keyboard-focusable scroll regions. Reflow is not a claim
that browser zoom itself was exhaustively tested.

The colour pass found a real low-contrast arrow colour in the flow strips; the
Encounter style owner now supplies a darker colour. The browser also exposed
that reload should remember the current project rather than reopen the oldest
entry. Both were corrected in source. A browser interaction timeout was resolved
by inspecting the resulting version, rather than submitting the save twice.

### Honest boundaries

This release provides the working seven-app composition above. It does not
complete every capability of the broader professional-suite vision:

- Import is supported plain text/Markdown or a compatible Studio packet.
  Project decompilation means checked recovery of maintained source, not lossless
  recovery from arbitrary Office, PDF, image or media binaries.
- Editing is source-and-preview, not a complete Office or nonlinear media editor.
  Native DOCX/XLSX/PPTX, production audio/video encoding and arbitrary binary
  assets still require qualified adapters.
- Commentary anchors identified record bodies and their rendered context. Finer
  section, range and individual quantity-property anchors remain future work.
- Selected standards currently provide three presentation profiles, terminology
  mappings and recorded accessibility/licence requirements. Recorded requirements
  are not evidence that every possible standard or accessibility rule is enforced.
- Attribution is self-supplied. There is no authenticated concurrent editing,
  protected multi-user data store, automated peer-history merge, live marketplace
  or payment settlement. An inspect/review step is not falsely reported as a
  completed human judgment.
- Data lives in this browser's local storage. The profile declares eight projects,
  32 records, 16 inputs, 16 calculations, 12 retained versions, 4,000 characters
  per record body and a 1.8 MB project packet. The unchanged execution budget can
  refuse an operation before a structural ceiling; maximum-capacity performance
  is not established by the small professional example.
- Receipts are bound to the exact process identity. This first release does not
  silently migrate incompatible prior process versions. Old data is retained
  and refused; a qualified migration is a separate capability.

These boundaries are exposed in the application's guide. They must remain
visible when describing or extending this release. Deployment is not admission
of the entire long-term product vision.
