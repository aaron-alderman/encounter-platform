# A bounded Encounter broadcast extension

Reason: make the video treatment editable and inspectable through the existing language/algebra technique. Target: authored clip facts, timed presentation decisions and their local media projection. Goal: one CLI and one production surface over the same checked composition.

## Actual semantic path

```text
composition.rel + contracts.rel + composition.encounter
                        ↓
existing ec.prepare → compiler → closed contracts → lowerer/admission
                        ↓
existing ec.run → typed Cut projections and declared reverse routes
                        ↓
broadcast.plan + source/project.json + source/graphics.json + media observations
                        ↓
frame-exact render plan + continuity decisions + selected graphic recipes
                        ↓
explicit Pillow/NumPy/FFmpeg media mechanisms → MP4 + receipts
```

The command host supplies inputs and mechanisms. It does not parse an invented Encounter dialect. The existing compiler handles real `view`, `representation`, `given`, `return`, `render` and `edit ... through` syntax. The existing type checker and projection/runtime supply typed values and exact edit destinations. `ec.patch` compiles and forward-verifies a changed source before the broadcast rules permit a local file replacement.

## Native media boundary

`source/graphics.json` owns which raster components participate in a layout, their geometry, text sources, entrance and hold values. `broadcast.plan` selects the recipe with the same layout value used by the CLI and studio. Python interprets the selected recipe using named primitives: title fitting, caption flow, perspective grid, cube projection, star seal, shapes, ticker and source-RMS meter.

The renderer additionally supplies explicitly native VHS colour delay/scanlines/tracking, geometric image transitions, audio-level matching, fades, decoding and encoding. These are a new bounded media mechanism profile. They have not been translated into the existing algebra, and this extension does not establish a pure or self-hosting Adobe-equivalent media engine. The rendered receipt names and hashes its native closure; the plan names its semantic closure.

The studio's JavaScript controls playback and projects the plan. Its inspector sends a source proposal, not an accepted client graph. It exposes the same source identity and edit routes returned by the runtime. No alternative mutable project store or inference of arbitrary inverse edits is introduced. Rendering is explicit because recomputing the native video is distinct from updating an authored decision.

## Local effects and retention

The CLI writes only this new application's source owner, task-local artifacts and retained predecessors. It serves loopback, streams a bounded set of source IDs and its own output, and requires a session token for edit/render requests. HTTP byte ranges support programme/source seeking. It neither uploads nor publishes material.

Local proposals use a source basis, forward verification, broadcast validation, predecessor capture and a staged single-file replacement. A single server serializes these requests. Independent external writers and arbitrary crash durability require a stronger protocol; this is not the signed-human Slice 02 retention owner. Its limitations are recorded rather than treating a local success as platform admission.

Render work uses a separate exclusive lock and an immutable plan snapshot. A previous video is retained before a successor is staged. Media hashes are checked again before rendering; a stale source requires new observations and compilation. Output bytes, frame count, format and audio checks are independently observable at the native boundary, within the same run's evidence family.
